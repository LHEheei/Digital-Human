# 情绪识别质量验收协议

## 评估范围

评估 Android 数字人项目的面部、语音和融合情绪识别。类别固定为 `neutral`、`joy`、`sorrow`、`angry`、`surprised`。

记录运行模式、目标类别、输出类别、分数、耗时和错误类别；原始人脸图像、音频、截图及模型缓存不进入评测记录或 Git。

开发包提供情绪诊断与评测面板；普通演示包默认隐藏。感知标签描述用户线索，数字人的表情由回复语义决定，不应以两者标签一致作为动作验收标准。

## 测试前置条件

1. 记录 APK 版本、手机型号和运行模式：`AndroidOnDeviceFace` 或 `LanService`。
2. 确认情绪感知已启用，相机和麦克风权限已授予；语音对话测试需配置有效 DeepSeek Key，并等待应用进入“正在聆听”。
3. `LanService` 模式需运行 Python 服务，确认电脑的 `http://127.0.0.1:8000/health` 返回 `status: ok`。USB 联调执行 `adb reverse tcp:18000 tcp:8000`，应用服务地址设为 `http://127.0.0.1:18000`；Wi-Fi 联调使用电脑局域网地址。
4. 使用前置摄像头，单人正面入镜，距离约 50–70 cm，光线均匀。等待首个有效面部结果后开始测试。

## 面部测试

每个类别做 3 轮；每轮保持至少 3 秒，记录最后一次稳定的面部标签和分数。若结果仍在变化，继续保持并记录稳定耗时。两轮以上匹配目标类别即通过。

| 目标 | 动作提示 | 通过标准 |
| --- | --- | --- |
| neutral | 自然放松，不抿嘴、不皱眉 | 至少 2/3 为 `neutral` |
| joy | 清晰露齿或不露齿微笑，双侧嘴角同时上扬 | 至少 2/3 为 `joy` |
| sorrow | 双侧嘴角下压、眉头轻抬或内收，动作保持稳定 | 至少 2/3 为 `sorrow` |
| angry | 双侧眉头下压，同时轻抿嘴 | 至少 2/3 为 `angry` |
| surprised | 双眼睁大、眉毛上扬、嘴微张 | 至少 2/3 为 `surprised` |

记录目标、轮次、输出、稳定耗时，以及无人脸、多人脸或服务错误。端侧模式对明确的当前帧信号直接响应，对模糊结果使用时序平滑；局域网服务采用 5 帧窗口的稳定判断。

## 语音测试

应用进入“正在聆听”后，以正常音量在约 15–30 cm 距离连续说完一句。每类做 3 轮，等待语音结果刷新后记录标签和分数。

- **端侧模式**：分析本轮 ASR 共用音频；对话最多等待语音情绪 150 ms，之后的结果可继续刷新。语音模型输出 `sorrow` 时，还会结合识别文本或新鲜面部结果校准，记录时一并保留对应标签和测试语句。
- **局域网模式**：分析持续采集的语音窗口，默认 4 秒；ASR 占用麦克风期间暂停窗口采集。复测时确认窗口覆盖了测试语句。

| 目标 | 建议语句与语气 |
| --- | --- |
| neutral | 平静匀速地说：“我正在做今天的测试。” |
| joy | 明亮、上扬地说：“太好了，我真的很开心！” |
| sorrow | 放慢、低沉地说：“我今天有一点难过。” |
| angry | 较重、坚定但不喊叫地说：“这件事让我很生气。” |
| surprised | 短促、上扬地说：“真的吗？太意外了！” |

语音通过标准：每类至少 2/3 输出与目标相同。`No clear speech detected` 记为采集失败，单独统计并重测一次；准确率使用有效采集样本计算。持续安静时出现该提示属于预期行为。

## 融合测试

在两路都有新鲜结果后检查综合结果，按运行模式使用对应预期。

| 情况 | Android 端侧 | 局域网服务 |
| --- | --- | --- |
| 两路一致 | 同类别权重相加，面部系数 1、语音系数 0.85；达到 0.5 后输出，分数上限 1 | 输出同类别，分数为面部 × 0.55 + 语音 × 0.45 |
| 单路可用 | 加权分数达到 0.5 时采用该路，否则输出 `neutral` / 0.45 | 通过阈值检查后采用该路，分数上限 0.75 |
| 两路冲突 | 取加权分数较高的类别，最高权重低于 0.5 时输出 `neutral` / 0.45 | 输出低于 0.5 的 `neutral` |
| 面部超过 3 秒或语音超过 6 秒 | 过期通道排除在融合输入外 | 过期通道排除在融合输入外 |
| 两路均无有效结果 | 输出 `neutral` / 0.45 | 返回无新鲜有效结果的错误 |

时效检查以结果时间戳和融合输入为准。服务预热、连接失败和采集失败分别记录，便于定位问题。

## 问题分流

- **局域网服务 502 / HTTP 0**：检查 `/health`、应用服务地址与 ADB 转发或 Wi-Fi 连通性。
- **No face**：检查前置画面、单人入镜、人脸完整度、光线和距离。
- **连续误判为 angry**：记录原始分布与稳定后标签，检查光线和裁剪，再复测中性与目标表情。
- **连续 No clear speech**：检查采集窗口是否覆盖语句，靠近麦克风并减少背景噪声，按采集失败记录。
- **融合与单项不同**：核对运行模式、两路时间戳及对应权重规则。

## 调参原则

先完成记录，再逐项调整阈值、稳定帧数或融合权重。每次调整后重跑同一协议，对比各类别结果。
