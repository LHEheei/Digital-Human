# 情绪识别质量验收协议

## 目的与边界

此协议用于评估 Android 数字人项目的面部、语音和融合情绪识别质量。仅记录目标类别、输出类别、置信度、耗时和错误类别；**不保存或提交人脸图像、音频、截图或模型缓存**。

首版类别固定为：`neutral`、`joy`、`sorrow`、`angry`、`surprised`。

## 测试前置条件

1. 手机通过 USB 调试连接电脑；`adb reverse tcp:18000 tcp:8000` 已建立。
2. `http://127.0.0.1:8000/health` 返回 `status: ok`。
3. App 顶部 API 指示为绿色；相机和麦克风权限已授予。
4. 使用前置摄像头，单人入镜，正面、约 50–70 cm 距离，避免强逆光。
5. 启动后先保持自然中性表情约 10 秒，等待“建立中性表情基线”结束。

## 面部测试

每个类别做 3 轮；每轮保持 3 秒，记录最后一次稳定的“面部表情 / 置信度”。两轮以上匹配目标类别即通过。

| 目标 | 动作提示 | 通过标准 |
| --- | --- | --- |
| neutral | 自然放松，不抿嘴、不皱眉 | 至少 2/3 为 `neutral` |
| joy | 清晰露齿或不露齿微笑，双侧嘴角同时上扬 | 至少 2/3 为 `joy` |
| sorrow | 双侧嘴角下压、眉头轻抬或内收，动作保持稳定 | 至少 2/3 为 `sorrow` |
| angry | 双侧眉头下压，同时轻抿嘴 | 至少 2/3 为 `angry` |
| surprised | 双眼睁大、眉毛上扬、嘴微张 | 至少 2/3 为 `surprised` |

记录项：目标、轮次、输出标签、置信度、是否出现 `No face` / 多人脸 / 服务错误。

## 语音测试

点击 MIC 后，以正常音量在约 15–30 cm 距离连续说完一句。每类做 3 轮；等待 4 秒语音窗口和结果刷新后记录“语音 / 置信度”。语音模型主要依据声学语气，不以文字内容作为唯一判断依据。

| 目标 | 建议语句与语气 |
| --- | --- |
| neutral | 平静匀速地说：“我正在做今天的测试。” |
| joy | 明亮、上扬地说：“太好了，我真的很开心！” |
| sorrow | 放慢、低沉地说：“我今天有一点难过。” |
| angry | 较重、坚定但不喊叫地说：“这件事让我很生气。” |
| surprised | 短促、上扬地说：“真的吗？太意外了！” |

语音通过标准：每类至少 2/3 输出与目标相同；`No clear speech detected` 记为采集失败，不计入类别准确率，需重测一次。持续安静时出现该提示属于预期行为。

## 融合测试

在面部与语音都获得新鲜结果后，检查“整体建议”。

| 情况 | 预期 |
| --- | --- |
| 面部和语音一致 | 输出相同类别，且置信度不低于任一单路的保守值 |
| 单路可用 | 采用可用单路，但置信度受上限约束 |
| 两路冲突 | 输出低置信度 `neutral`，不做强烈判断 |
| 面部超过 3 秒或语音超过 6 秒 | 该路显示“已过期”，不参与融合 |
| 服务暂时预热 | 显示“情绪模型正在预热”，随后自动重试；不应出现网关 502 |

## 问题分流

- **服务 502 / HTTP 0**：先检查 `/health` 和 ADB 转发；不要先调分类阈值。
- **No face**：先看诊断相机预览是否是前置画面、单人且人脸完整可见；再检查光线和距离。
- **连续误判为 angry**：确认中性基线已完成，再复测双侧眉毛和嘴部动作是否同时存在。
- **语音连续 No clear speech**：靠近麦克风、连续说完整句、减少背景噪声；这不是模型类别误判。
- **融合与单项不同**：先核对两路是否新鲜且是否冲突，再判断融合权重问题。

## 调参原则

先完成完整记录，再只改一项参数（阈值、稳定帧数或融合权重）并重跑同一协议。不要依据单次表情或单次录音调整模型逻辑。
