# 对话、逐句动作与记忆管理

日期：2026-09-20。Unity 6000.4.6f1。实现范围为逐句表情与手势、正式聊天界面、长期记忆管理三项。

## 使用方式

1. 在 Unity 打开 `Assets/Scenes/DesktopAvatarDemo.unity`，进入 Play Mode；也可使用 **SRTP → Dialogue Workbench → 打开演示场景并运行**。
2. 在 Game 窗口下方（横屏为右侧）输入消息，点击“发送”。等待期间显示状态和已到达的回复，可点击“停止”。
3. 未完整提交的失败或取消轮次显示“重试”。重试新建一轮，保留原失败记录；已经提交、仅播放期间中止的回答不会自动重发。
4. 点击“记忆”，选择条目后修改或删除。保存后立即更新本地文件，下次模型请求会使用新内容。
5. 编辑器默认离线模拟；在 Dialogue Workbench 可以切换故障场景、改变回复与记忆内容。真实模型需要已有 API 配置，只有发送后才调用服务。

## 行为与边界

- 文字和语音共用对话流程。文字发送先取消并等待正在占用 ASR 的会话退出，避免录音任务与手动对话重叠。编辑输入框和打开记忆面板期间暂停自动聆听，退出交互后按配置恢复。
- 可滚动历史保存当前会话最近 40 轮，含失败时已收到的部分文字与错误。历史不会写入磁盘。模型短期上下文仍保留 6 轮；长期记忆沿用原有容量配置。
- 句子按中文/英文问号、叹号、中文句号、分号和换行切分，与已有流式队列保持一致。实际播放开始时触发本地文本规则；Android 接收 `TtsStarted`，编辑器接收本地预览开始事件。
- 问候首句挥手，共情/肯定句点头，解释句使用解释手势。动作有跨轮冷却：任意动作 2.5 秒，同类 7 秒，挥手 12 秒。自然句尾允许已开始的动作完成；后一句没有新手势时，保留正在执行的动作。用户停止、播放失败、切换为聆听或思考时平滑收势，短促点头可在状态切换时完成。
- 元数据未返回时使用中性表情及当前句子的本地规则；已返回后以其表情为默认值，规则可以覆盖。完整 JSON 到达不会突然重播整段动作。该能力是规则驱动的句子级表现，不是逐词情绪理解或音素级动作对齐。
- 记忆编辑最多 80 字，沿用敏感信息过滤，拒绝与另一条相同的内容。旧格式兼容读取并分配 ID；下次成功保存写入版本 2。ID 在修改和重复记忆更新时保留，创建时间不变。
- 编辑和删除均先原子更新 `.bak`，再原子更新主文件，成功后发布内存中的新数据。两份文件不是跨文件事务：若主文件写入失败，会报告失败并保留当前内存/主文件，备份可能已经反映修改；重试可完成更新。成功删除或修改后不会从备份恢复出旧内容。
- 模拟与真实桌面模式保留独立历史、上下文及临时记忆，不修改正式手机记忆。手机上的记忆保存在 `Application.persistentDataPath/avatar_long_term_memory.json`。
